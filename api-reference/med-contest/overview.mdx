## Visão Geral

A API de **Contestação de MED** permite que parceiros respondam a uma solicitação de MED (Mecanismo Especial de Devolução do Pix) sem precisar acessar o painel.

Convive com os endpoints internos `/med-contest` (autenticados via JWT do painel) — todas as rotas para parceiros ficam sob o segmento `/med-contest/exposes` para evitar conflito.

<Note>
  As rotas usam a mesma autenticação da API (headers `api_key` e `api_secret`). As credenciais estão em **Configurações → Credenciais de API** no painel.
</Note>

## Autenticação

Todas as rotas exigem dois headers:

| Header       | Descrição                  |
| ------------ | -------------------------- |
| `api_key`    | Chave de API da conta      |
| `api_secret` | Secret de API da conta     |

**Rate limit:** 200 requisições/minuto por usuário.

## Fluxo recomendado

<Steps>
  <Step title="Recebimento do webhook">
    Parceiro recebe webhook IN com `transactionStatus = "MED"` (transação foi contestada pelo pagador).
  </Step>
  <Step title="Criar disputa">
    Parceiro chama `POST /med-contest/exposes` com o `transaction_id` (UUID) recebido no webhook. Cria o registro de disputa com status inicial `WAITING_CONTENT`.
  </Step>
  <Step title="Enviar evidência">
    Parceiro envia a evidência (arquivo + descrição) via `PATCH /med-contest/exposes/:medId`. Pode ser chamado múltiplas vezes para anexar mais de uma evidência — a última prevalece no campo `content`.
  </Step>
  <Step title="Resolução pelo PSP">
    Internamente, o gateway envia a defesa para o PSP upstream (hoje suportado: Woovi). Status muda para `DEFENSE_SUBMITTED` (sucesso) ou `DEFENSE_FAILED` (falha de transporte). A resolução final chega via webhook com `medStatus` igual a `APPROVED`, `REJECTED`, `REFUNDED` ou `CANCELLED`.
  </Step>
</Steps>

## Endpoints

| Método | Endpoint                          | Descrição                                            |
| ------ | --------------------------------- | ---------------------------------------------------- |
| POST   | `/med-contest/exposes`            | Abrir disputa de MED a partir do UUID da transação   |
| GET    | `/med-contest/exposes`            | Listar disputas de MED da conta (paginado, com filtros) |
| GET    | `/med-contest/exposes/:medId`     | Detalhar uma disputa (inclui evidência em base64)    |
| PATCH  | `/med-contest/exposes/:medId`     | Enviar evidência (arquivo + descrição)               |

## Status da disputa (`MedContest.status`)

| Status              | Significado                                                                       |
| ------------------- | --------------------------------------------------------------------------------- |
| `WAITING_CONTENT`   | Disputa criada, aguardando upload da evidência.                                   |
| `REQUESTED`         | PSP da transação não tem caminho server-to-server suportado — tratado manualmente. |
| `DEFENSE_SUBMITTED` | Defesa entregue ao PSP com sucesso.                                               |
| `DEFENSE_FAILED`    | Falha ao entregar defesa ao PSP. Retry possível chamando o PATCH novamente.       |
| `APPROVED`          | PSP aceitou a defesa — valor permanece com o parceiro.                            |
| `REJECTED`          | PSP rejeitou a defesa — estorno realizado em favor do reclamante.                 |
| `REFUNDED`          | Estorno efetivamente devolvido ao reclamante.                                     |
| `CANCELLED`         | MED cancelado.                                                                    |

<Info>
  Apenas a Woovi está integrada server-to-server hoje. Para outros PSPs o gateway aceita o envio normalmente, mas o tratamento volta a ser manual (sem mudança de contrato).
</Info>
