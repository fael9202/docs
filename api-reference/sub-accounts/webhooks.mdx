## Visão Geral

Enviamos webhooks sempre que o processo de KYC da subconta é concluído. Os eventos são disparados imediatamente após a decisão (aprovação ou rejeição) e chegam via **POST** na `callback_url` configurada para webhooks de subcontas.

### Campos comuns no payload

| Campo | Descrição |
|-------|-----------|
| `event` | Nome do evento (`kyc.approved` ou `kyc.rejected`) |
| `timestamp` | Momento em que o evento foi gerado (UTC), formato ISO 8601 |
| `user` | Dados básicos da subconta impactada: nome, email, documento (CPF/CNPJ) |

## Eventos

### kyc.approved

Enviado quando o KYC da subconta é **aprovado**.

```json
{
  "event": "kyc.approved",
  "timestamp": "2026-01-15T21:06:03.628Z",
  "user": {
    "name": "joao gomes",
    "email": "teste@email.com",
    "document": "1111111113"
  }
}
```

### kyc.rejected

Enviado quando o KYC da subconta é **rejeitado**.

```json
{
  "event": "kyc.rejected",
  "timestamp": "2026-01-15T21:08:07.876Z",
  "user": {
    "name": "joao gomes",
    "email": "teste@email.com",
    "document": "1111111113"
  }
}
```
